### A9. ON FIRE path — critical timer-side-effect audit
- **Fire path (lines 6508–6522):**
  1. Manipulates `#jarvis-btn` CSS only (add/remove `.listening`, ripple scale).
  2. Calls `openPanel()` then `startListening()`.
  3. **Does NOT call `clickStart()`, `q('[data-act="start"]')`, or dispatch any event to a timer button.**
- **⚠ Important finding:** The fire path is CLEAN — it cannot directly start the timer. However, the bug report says clap-to-wake sometimes starts the timer. Most likely cause: after the clap fires `startListening()`, the STT engine briefly picks up ambient sound as a command and matches a timer-start regex (e.g. a fan/AC hum near "start" phonetics). This is a false STT match, not a DOM event leak from clap. Phase 2 gates (G4: `_state !== 'listening'`) help but may not fully prevent it if the false fire happens before the state updates. **Flag to Om:** please confirm whether the timer starts immediately at the clap sound vs. ~1–2 seconds later — the delay would confirm it's an STT false positive.
